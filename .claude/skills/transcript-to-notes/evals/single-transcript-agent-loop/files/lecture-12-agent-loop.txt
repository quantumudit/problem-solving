So what is an agent really? An agent is just an LLM running in a loop with access to tools. That's it. The model gets a goal, it decides whether to call a tool or to answer, we run the tool, we feed the result back to the model, and we repeat until the model says it's done. Okay? Now there are two big patterns people use. The first is called react, R E A C T, which stands for reason and act. In react the model decides one step at a time. It thinks, picks a tool, sees the result, and then thinks again. The advantage is that it is very flexible, it can change its mind when a tool result surprises it. The downside is that it can wander. It can loop forever, and it costs more because every step is a full model call with the whole history.

00:01:44
The second pattern is plan and execute. Here the model first writes a whole plan, a list of steps, up front. Then a separate executor goes through the steps one by one, and maybe a cheaper model does the executing. The plus side is it's cheaper and more predictable, and you can show the plan to a human to approve. The minus is that it's rigid, if step two fails the plan might be wrong and you need a re-planning step.

00:02:30
So when do you pick which? If the task is open ended, like debugging some unknown error, go with react. If the task is well understood, like generate a weekly report from three known data sources, plan and execute is usually better.
